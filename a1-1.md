# Activity 1 – Step 1: A vague prompt

**Chatbot / model:** <!-- e.g., ChatGPT (GPT-5), Gemini, Claude / เช่น ChatGPT (GPT-5), Gemini, Claude -->

## Prompt

```text
Create tests for a file upload feature
```

## Response

## Functional Testing

* **Single File Upload:** Verify a user can successfully upload a file with a supported extension and size.
* **Multiple File Upload:** If supported, verify multiple files can be selected and uploaded simultaneously.
* **Drag and Drop:** Verify files can be uploaded by dragging them from the OS into the designated drop zone.
* **File Explorer Trigger:** Verify clicking the "Upload" button correctly opens the native OS file picker.
* **File Metadata:** Verify that after upload, the file name, size, extension, and timestamp are correctly displayed and stored in the database.
* **File Preview:** Verify that uploaded images or documents render a correct thumbnail or preview if the UI supports it.
* **File Download/Access:** Verify the uploaded file can be successfully downloaded or opened, and the data is not corrupted.

## Boundary & Validation Testing

* **Maximum File Size:** Upload a file that is exactly the maximum allowed size (e.g., exactly 5MB).
* **Over Maximum Size:** Upload a file that exceeds the maximum size limit (e.g., 5.01MB) and verify the appropriate error message is triggered.
* **Zero-Byte File:** Upload an empty (0 KB) file and verify the system handles it gracefully (typically by rejecting it).
* **Invalid File Type:** Attempt to upload a file format that is not on the accepted list (e.g., uploading a `.pdf` when only `.jpg` is allowed).
* **Long File Name:** Upload a file with a name exceeding standard character limits (e.g., >255 characters) to test database/storage truncation errors.
* **Special Characters:** Upload a file containing special characters in the name (e.g., `test_file!@#$%^&*().jpg`) or spaces to ensure it does not break file paths or URLs.

## Security Testing

* **Extension Spoofing:** Change the extension of an executable file (e.g., renaming `malware.exe` to `malware.jpg`) and verify the server inspects the MIME type/file header and rejects it.
* **Double Extensions:** Upload a file with multiple extensions (e.g., `script.php.jpg`) to ensure backend parsers do not execute the hidden script.
* **Cross-Site Scripting (XSS):** Upload a file with a malicious script as the file name (e.g., `<script>alert('xss')</script>.jpg`) to verify the file name is sanitized when displayed back on the UI.
* **Path Traversal:** Intercept the upload request and inject path traversal characters (e.g., `../../../etc/passwd` or `..\..\windows\system32`) into the file name parameter to test if files can be saved outside the intended directory.
* **Large Payload (Denial of Service):** Attempt to upload an extremely large file (e.g., 10GB) or send thousands of requests simultaneously to check for rate limiting and server timeouts.

## Error Handling & Network Testing

* **Cancel Upload:** Start an upload and cancel it midway. Verify the partial file is not saved on the server and temporary data is cleared.
* **Network Interruption:** Disconnect the internet midway through an upload. Verify the system shows a network error message and allows the user to retry once reconnected.
* **Server Timeout:** Simulate a slow network connection to ensure the application handles upload timeouts gracefully without freezing the UI.
* **Storage Full:** Simulate a scenario where the target server or cloud bucket runs out of storage space and verify the error is handled cleanly without exposing stack traces to the user.

## UI/UX Testing

* **Progress Indicators:** Verify a progress bar or percentage indicator accurately reflects the upload status for large files.
* **State Changes:** Verify the upload button is disabled while an upload is in progress to prevent duplicate submissions.
* **Error Visibility:** Ensure error messages (e.g., "File too large") are prominently displayed, colored appropriately (usually red), and easy to understand.
* **Responsive Design:** Verify the upload component functions and scales correctly on mobile, tablet, and desktop viewports.
